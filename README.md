# intj

一个以 README 为核心的 Claude Code 界面。背后仍由 `claude` CLI 驱动，人和 Claude 之间的交流发生在 README 里。

## 为什么要做

Chat 界面是线性的。项目一大，这种结构会出几个问题：

- **上下文会丢。** 对话一长就被压缩，早期的决策和约束在摘要里消失。
- **多条线索混在一起。** 前端、后端、部署的讨论挤在同一条时间线上，互相污染上下文。
- **决策难回溯。** 要知道"当时为什么这样定"，得翻几百条消息。
- **没法并行。** 一个会话同时只能推进一件事。

大型项目本来就是树状的：模块、子模块、任务。intj 让界面也变成树，每个节点用一份 README 承载。

## 核心概念

**节点 = 一个目录 + 其中的 `README.md`。** 整个项目是一棵 README 树：

```
project/
├── README.md            ← 根节点：愿景、全局约束、模块划分
├── backend/
│   ├── README.md        ← 模块节点
│   └── auth/
│       └── README.md    ← 任务节点
└── frontend/
    └── README.md
```

README 同时承担三个角色：

1. **规格**：人写下要什么。
2. **状态**：Claude 写下做到哪了、卡在哪。
3. **记忆**：决策和理由留在这里，任何新会话读 README 就能接上，不依赖聊天记录。

聊天会话是一次性的，用完即弃。README 是持久的。

## README 模板

每个节点的 README 分成固定几节，每节有明确的归属：

```markdown
# <节点名>

## 目标                ← 人写
这个节点要达成什么，完成的标准是什么。

## 规格                ← 人写，Claude 可提建议
接口、约束、边界条件、不做的部分。

## 状态                ← Claude 写
- [x] 已完成的事
- [ ] 进行中 / 待做

## 问题                ← Claude 提问，人在下方回答
- Q: token 过期时间定多久？
  A: 24 小时。

## 决策                ← Claude 记录，人确认
- 2026-09-18 选用 JWT，原因：无状态、便于水平扩展。

## 子节点              ← Claude 拆分时维护
- [auth/](auth/README.md) — 登录与鉴权
```

规则：Claude 不改"目标"；要改"规格"时在"问题"里提出，由人落笔。

## SOP

一个节点的工作循环：

1. **写意图。** 人在节点 README 的"目标"和"规格"里写下要什么。新节点就新建目录和 README。
2. **派发。** 对该节点启动一次 Claude Code 会话（见下文"上下文组装"）。
3. **执行。** Claude 在节点目录内写代码、跑测试。
4. **回写。** 会话结束前，Claude 必须更新 README 的"状态"、"问题"、"决策"。任务太大时，Claude 拆出子节点，为每个子节点写好目标草稿，交人确认。
5. **审阅。** 人看 README 的 git diff 和代码 diff，不读聊天记录。在"问题"下回答，按需修改规格。
6. **提交。** 一轮结束 commit 一次，README 和代码一起进版本历史。
7. **循环。** 有未答问题或未完成状态，就回到第 2 步。

节点完成的标准：状态全部勾选，问题全部回答，目标里的完成标准满足。

## 上下文组装

每次派发，会话拿到的上下文由树的结构决定：

- **祖先链**：从根到当前节点路径上的所有 README，提供全局约束和上层决策。
- **当前节点**：完整 README 和目录内代码。
- **子节点摘要**：每个子节点 README 的"目标"和"状态"。
- **兄弟节点**：默认不加载，需要时由 README 显式链接。

这样每个会话的上下文小而准，和树的深度成正比，和项目历史长度无关。

## 并行

不同节点互相独立，可以同时派发。每个并行会话在自己的 git worktree 里跑，完成后合并。两个节点要改同一处代码时，说明边界划错了，回到父节点调整拆分。

## 由 Claude Code CLI 驱动

intj 不重新实现 agent，派发就是一次 `claude` 调用：

```bash
cd project/backend/auth
claude -p "$(intj context .)" \
  --append-system-prompt "$(cat intj-rules.md)"
```

- `intj context <node>` 按上文规则拼出祖先链、当前节点、子节点摘要。
- `intj-rules.md` 写明 README 各节的归属和回写要求。
- 需要人实时介入时，去掉 `-p` 进入交互模式，规则相同。

## 路线图

- [ ] `intj-rules.md`：Claude 在节点内的行为规则
- [ ] `intj context`：上下文组装脚本
- [ ] `intj run`：派发一个节点（含 worktree 管理）
- [ ] 树状视图：一眼看到所有节点的状态和未答问题
